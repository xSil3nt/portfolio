01Professional introduction

How I work
as an engineer.

I am a final-year Computer Engineering student focused on embedded systems, robotics, simulation, and software for physical systems. Most of my work involves connecting hardware, communications, and software into one working system.

My main examples are low-power sensor nodes, an autonomous payload drone, a multi-robot agricultural simulation, and an open-source contribution to OrcaSlicer. I tend to learn by building, measuring failures, and iterating until the behaviour is understood.

The weakness in that approach is that implementation can begin before the requirements and test plan are formalised. I need to put more work into validation, standards, cost analysis, and documentation before treating a system as complete.

02SWOT analysis

Current strengths
and gaps.

S / Strengths

Cross-layer implementation

I can work across hardware, firmware, backend systems, and interfaces, and I am comfortable learning unfamiliar tools independently.

W / Weaknesses

More breadth than depth

I have limited experience with formal compliance and engineering economics, and several projects are still prototypes rather than production systems.

O / Opportunities

Improve the work already built

I can deepen the real-time and robotics work, add better validation, and use code review and professional feedback to find weak assumptions.

T / Threats

Limited hardware, data, and time

Without representative hardware or field data, it is easy to overestimate a prototype. Time pressure can also reduce testing depth.

Development direction

Work on fewer projects in more depth. Each major project should include requirements, a test plan, known limitations, external review, and at least one cost or standards check.
